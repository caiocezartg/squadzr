# Redesign v2 — design reference

The implementation contract for the Redesign v2 screens. It is extracted from the canvas snapshot in this folder (`*.dc.html`, `screens/*.png`) and adds what the canvas leaves open: responsive behaviour, motion values and the deviations the product decisions require.

When this file and an artboard disagree, this file wins. When this file is silent, match the artboard and its PNG. Every styling or motion decision is checked against the `emil-design-eng` skill.

### Spacing and layout

- App shell: sidebar column 260px (`menu` ground, `inset -1px 0 0 #16171B` edge), main padding `30px 40px 48px`, vertical rhythm 18px.

- Touch targets are at least 44px tall on every interactive control (36px only for `sm` buttons inside desktop panels).

## 2. Components

Each component lives once in the client's UI layer and is reused by every screen. Variants and states follow the artboard named in brackets.

- **Button** (`Button.dc.html`): variants `primary`, `secondary`, `ghost`, `link`, `danger`, `discord`, `light`, `dark`, `glass`; sizes `sm` 36px, `md` 44px, `lg` 56px; icon at start or end; icon-only square; `mono` for codes; renders a link when it navigates. Disabled ground `track`, text `faint`. Every variant presses to `scale(0.97)`.
- **Tag** (`Tag.dc.html`): read-only `tag` (`#label`), `glass`, `lang` (globe icon), `lang-light`, `platform` and `platform-light` (the Squad's platform: the family's mark from `PlatformIcon` and the short label: Windows for PC, PlayStation for PS5 and PS4, Xbox for both Xboxes, Nintendo Switch for both Switches and a phone for Mobile, one colour (`currentColor`), paths from Bootstrap Icons (MIT); the mark is decorative and the colours are the language chip's, `platform-light` being the twin of `lang-light` for the Lobby's dark cover; it sits right after the language chip on the card and in the Lobby, and a Squad without a platform shows none); buttons `toggle` (`aria-pressed`; with `choice` it is one radio of a `radiogroup`, with no `#`, used for the platform in the create form and in the board filter, where each chip carries the Platform's mark), `suggest` (`+ #label`), `removable` (× with an accessible "remove" label; the platform filter chip carries the Platform's mark).
- **Avatar** (`Avatar.dc.html`): sizes 28/34/36/44; states `online` (mint ring with the halo pulse), `away` (grayscale 0.85, opacity 0.5, dashed outline), `open` (empty slot with a plus and the wait pulse), `vacant` (grey slot on cards), `none`; host crown on top. Shows the player's Discord image when present, otherwise initials on a colour pair picked deterministically from the player id (palette below).
- **Avatar palette** (bg / fg): `#0E4D3A/#B9FFE4`, `#3A2A5C/#E7DBFF`, `#5C3A1E/#FFE2C7`, `#1E3A5C/#CFE6FF`, `#5C1E3A/#FFD1E6`, `#4A4A1E/#F4F4C2`, `#1E4A4A/#C6F4F4`.
- **MemberTile** (`MemberTile.dc.html`): 64px row, avatar `lg`, name, "você" for the viewer; online, away (with "Fora da sala · há X min" as its accessible presence text and tooltip) and open slot ("Vaga aberta"). Grounds: online `#15161A`, away `#111215`, open `#0C0D10` with a 1px `raised-2` inset.
- **SlotMeter** (`SlotMeter.dc.html`): `blocks` (Lobby, 40px segments, 18px above 5 slots), `line` (sidebar, card rails), `pips` (filter options); tones mint, discord (Ready), amber. More than 10 slots collapse to 10 segments.
- **Segmented** (`Segmented.dc.html`): `sm` mono (language switch) and `md` (squad language, sort, filter language); fluid option; `aria-pressed` buttons in a labelled group.
- **Pagination** (`Pagination.dc.html`): 44px squares (40 in `sm`), mint current page (light tone in the Lobby), disabled ends.
- **SearchField** (`SearchField.dc.html`): `field` (54px, ring `track`, ring `mint` with a value, clear button) and `bare` (inside the board bar); combobox mode for the game search.
- **Steps** (`Steps.dc.html`): three steps, 3px bars, mono labels, check on done steps, `aria-current="step"`.
- **NotificationItem** (`NotificationItem.dc.html`): cover 38×50 with a Discord badge, Squad name, "Convite do Discord liberado", game and relative time; unread shows a 2px mint edge, bold name and a dot; read covers go grayscale 0.6; dismiss button appears on hover and focus.
- **DiscordInvite** (`DiscordInvite.dc.html`): locked bar (lock icon, "Liberado quando o squad completar", masked `discord.gg/••••••••`) and the unlocked "Bora pro Discord" panel, which sits in the members column (see Deviations). The Ready panel is the display title over one translucent server card: a 52px icon with the Discord badge, "CONVITE DO SERVIDOR" and the server name; one call line under the server name, the muted label "Entre na call", a speaker icon and the voice call's name (a single line, truncated at phone width, absent when the Squad has no call); a link row with the invite and both actions (a glass "Copiar link" that turns into "Copiado" for 1.8s, and the light "Abrir no Discord"), over the Discord blurple with the faded logo watermark, or the server's banner (its splash when it has no banner) as a dim backdrop. The icon and name come from the Discord Preview the API reads from the invite, and the call from the Lobby's snapshot, so it shows with no request and no skeleton. Without the preview (missing, invalid or expired invite, Discord down or rate limiting) the card shows the game's cover and the Squad's name; the card keeps the same structure and height (the call line aside, which a Squad without a call does not have), and a skeleton shows in the icon and name only while a cold cache reads the preview for the first time. The locked panel has the same skeleton: the display title, a lock row, the slots left with the meter and the masked link over two dimmed actions, so the column does not jump when the Squad completes.
- **SquadCard** (`SquadCardHover.mockup.html`, issue #203): `md` (118px poster, 176px tall) and `lg` (160px poster, 214px tall), square, with the vertical poster. The ground is the game's colour: the cover (the poster's own URL) drawn behind the whole card with `blur(34px) saturate(1.6)` at opacity 0.68, overflowing it by 30% on each side and clipped by it, under a shade (`linear-gradient(90deg, rgba(10,11,14,.05) 0%, rgba(10,11,14,.55) 36%, rgba(10,11,14,.82) 100%)` plus `linear-gradient(180deg, transparent 45%, rgba(10,11,14,.5) 100%)`) on `#0d0e11`; a cover that fails leaves the plain ground. The other circles are 36px (28px on `md`), each under the one after it with a 3px ring of the ground; vacant seats use the avatar's `vacant` state. States: open (a button that joins), member (a link to the Lobby), full for a non-member (`aria-disabled`, grayscale poster and ground at opacity 0.35, "CHEIO" overlay in Anton, opacity 0.62, no hover), preview (a plain group: no viewer seat, hover, glow or arrival). No badge, ring or call to action. The card's accessible name reads "name — game, language, n de max jogadores". The "PRONTO" state only appears where Ready Squads are listed.
- **Sidebar** (`Sidebar.dc.html`): logo, "Criar squad", join-by-code form, "Todos os squads" with the open count, "Meus squads" (cover, host crown, name, line meter, count; amber count when one slot is left; Discord badge and discord tone when Ready; current item with a mint edge), language switch, user button with presence dot and menu.

### Deviations from the canvas

- Squad codes have **6** characters (the sidebar artboard says 5).
- The squad name counter reads `n/30`; the name limit stays 30.
- Player counts run **2 to 40**; every "2 a 20" in the copy becomes "2 a 40".
- Copy never names a fixed number of games; the hero badge and the games section read `totalGames` from the API.
- "Sugerir um jogo" in the empty search state is dropped: there is no destination for it.
- `/squads/my` does not exist; "Meus squads" lives only in the sidebar.
- The board's tag filter accepts several tags; a Squad matches when it has every selected tag, compared exactly (case-insensitive, without `#`).
- Create Squad's "Popular now" games are rows in the game search's listbox (cover, name, genre and size), not the artboard's six-column cover grid (`CriarSquad`), so arrow keys move through one list.
- Avatars use the player's Discord image when there is one; the initials palette is the fallback.
- The Ready invite panel is not a full-width band: from 1024px up it sits under the members panel, in the right column and as wide as the panel, with the cover panel on the left, and below 1024px the order is cover, members, invite. The canvas's 72px title above a 64px-cover server card and a separate link row becomes a 34px title (40px from a 672px-wide panel) over one translucent card with a 52px icon, one call line and the link row, and the "SQUAD FECHADO" badge is dropped. From 1024px the cover is 288px wide and the members column takes the rest, and from 1280px the column is 58% of the row, capped at 40rem (640px), so on big screens the extra width goes to the cover and the members panel and the invite never stretch; the cover drops its 3:4 ratio there and stretches to the column's height. The locked panel matches the Ready panel's rows (title, icon row, a 48px row of the call or the slots, link row). The card shows the Discord server's icon and name with the voice call to join, over the server's banner as a dim backdrop; without a preview it shows the game's cover and the Squad's name over the logo watermark.

## 4. Responsive

There are no mobile artboards, so these rules are the contract. Widths: narrow is below 640px, medium is 640–1023px, wide is 1024px and up. Tailwind's min-width prefixes implement them; never read a prefix as a range.

- **App shell:** at wide widths the sidebar is a fixed 260px column and the bell sits in the page header. Below 1024px the sidebar becomes a drawer opened from a top bar that holds the logo, the bell and a menu button (the page header then has no bell); the drawer slides from the left, traps focus, closes with Escape and returns focus to the menu button.
- **Squad Board:** 2 columns of large cards at wide widths, 1 column of medium cards below 1024px. The page title drops to 44px below 640px. Filters and notifications open as popovers from 640px up, and as bottom sheets below 640px.
- **Lobby:** cover panel on the left and, at wide widths, the members panel with the invite under it on the right, so the cover stretches to the height of the column; the page stops at 76rem and centers on wider screens, so a big screen keeps the 1440px composition instead of stretching the cover; stacked below 1024px (cover, members, invite), with the cover panel shortened to a 16:9 band. Member tiles: 2 columns from 640px up, 1 column below. Header actions wrap; below 640px the copy and leave actions become icon buttons with accessible labels.
- **Create Squad:** the modal is full screen below 640px, with the footer actions pinned to the bottom.
- **Landing:** the navigation collapses into a menu below 640px. Below 768px the hero headline takes four lines and keeps four of its six chips (see Hero). The games panel stacks above the list below 1024px. "Como funciona" is sticky only at wide widths (see Motion); below 1024px it is three stacked cards.
- Every screen is checked at 1440, 768 and 390px wide.

## 5. Motion

Values come from the canvas `.ds-` styles, corrected by the `emil-design-eng` rules.

### Tokens

| Token           | Value                                  |
| --------------- | -------------------------------------- |
| `--ease-out`    | `cubic-bezier(0.23, 1, 0.32, 1)`       |
| `--ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)`      |
| `--dur-press`   | 160ms                                  |
| `--dur-fast`    | 150ms (hover colour, chips, segmented) |
| `--dur-ui`      | 200ms (popovers, panels)               |
| `--dur-modal`   | 280ms enter, 180ms exit                |

### Rules

- Animate `transform` and `opacity` only. The FAQ accordion is the one height animation, and the Squad card's rail the one width animation (the viewer's seat opens and the last circle folds on hover, so the rail keeps its width).
- CSS transitions and `@starting-style` by default. The `motion` library only drives the scroll-linked "Como funciona", the in-view reveal and the realtime member entrances, always with full `transform` strings.
- Exits are faster than entrances.
- Hover effects sit behind `@media (hover: hover) and (pointer: fine)`.
- Content that arrives ready (server render or warm cache) never animates in. No route-level loading states.
- Keyboard shortcuts take effect without a transition: Escape closes at once, arrow keys move the active option without one. Content that changes as a result (a step, an accordion panel) keeps its normal transition.
- `prefers-reduced-motion: reduce` keeps opacity and colour changes and removes movement, scale and loops. "Como funciona" becomes the stacked cards.

### Hero

The hero takes the first screen, over the wall of covers, and tells one story once: "Chega de jogar solo", with SOLO struck out, then "Monte seu squad" as four players fill the visitor's squad. It runs on CSS from the first paint; the moments live in `client/src/components/landing/hero-timeline.ts`, the animations in `globals.css`.

1. **Solo (0–3.1s).** The headline, in Anton, reads "Chega de jogar solo". The letters of SOLO (`muted`) drift apart, each 0.09em further than the one before it (2800ms `--ease-in-out`). The visitor sits alone in the rail: a mint "VC" seat, four vacant ones and `1/5`. Around the headline the solo life rises in, one chip every 230ms from 250ms (520ms `--ease-out`, from 10px lower, `scale(0.94)` and a 4px blur), in this order: `fila solo · 18:42`, `procurando partida · 14 min`, `lobby · 1/5`, `convite pro duo · expirou`, `amigos online · 0`, `duo · offline`, each with an icon in a vacant seat's circle and its value in `danger`. Four players float close around the lettering (beside the first line and the rail; on phones beside "solo" and the line still to rise), a little larger than their seats (`scale(1.1)`), fully opaque and named; each bobs once.
2. **Strike (3.1s).** A mint strike draws through SOLO (560ms `--ease-out`) as its letters settle back together and dim to 30% (55% below 768px).
3. **Squad (3.58s).** "Monte seu squad" rises from below its line (900ms `--ease-out`) and the chips blur away, 45ms apart (420ms). From 3.8s the players fly into their seats, 110ms apart (1000ms `--ease-in-out`), dropping their names and settling to the seat's size; each seat flashes its mint ring as its player lands, and the counter rolls one step per landing to `5/5`, turning mint with the last.

It plays once and holds. Below 768px each line of the headline takes two and four chips show (no lobby, no friends); from 1280px all six do. The squad and the chips are decoration, hidden from assistive technology, and the struck word is read once. Every element rests in the story's end, so reduced motion shows SOLO struck, the second line in place and the squad full, with no chips. The story is the one exception to "content that arrives ready never animates in": its second line waits for the strike.

### "Como funciona"

- At wide widths, the section is a sticky stage inside a scroll track three viewports tall. The left column lists the three steps; the right shows the step's mockup.
- Scroll progress (motion's `useScroll` on the track) maps to the active step in thirds. The active step's numeral fills mint (the others stay outlined), and a 2px progress bar under each numeral fills linearly with its third.
- Mockups crossfade (opacity 300ms with a 2px blur bridge) when the active step changes. Inside each mockup the canvas's micro-animations play once on entry: the click on "Entrar com Discord", the search typing "valorant" and the pick, the last two members joining and the invite appearing.
- When the third step completes, the sticky stage releases with the rest of the page.
- Below 1024px and under reduced motion: three stacked cards with the section reveal, and the mockups in their final state.

## 6. Admin panel

The private panel at `/admin` (spec #116). The approved mockup is `AdminPanel.mockup.html` in this folder (copy in Portuguese, like the `pt-BR` catalog); this section adds what the mockup leaves open. It uses the foundations and components above in a denser, table-first layout.

- **Shell:** its own layout, not the app shell. A 232px sidebar (`menu` ground, same inset edge as the app's) holds the logo with a mint `ADMIN` badge, Overview, Squads, Users, Catalog and Audit (current item: `raised` ground and a 2px mint edge), then "Back to Squadzr" and the account button at the foot. The sidebar shows no counts. Main padding is `30px 36px 40px`.
